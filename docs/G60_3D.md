# G60 problems and hosted model

The sidebar has Overview, Problems, 3D model, Evidence library, Comparisons, and Decisions & audit. Problems and 3D model share a selection and can be merged side by side with **Merge tabs**. **Problems only** and **Model only** separate them again. Search, category, priority, decision status, sort and direction survive switching between these views. On narrow screens the merged model and list stack vertically.

Problems retain the ten C01–C10 categories, full requirement text, expandable source excerpts, original filenames and exact source locators. Clicking a source opens the existing original-evidence inspector. Scores retain distinct-record demand, its numerator/denominator, PM impact bands, critical review flags, positive mentions and decision status. Default ordering is critical first, then reviewed impact, then demand. Demand is a potential-reach proxy; benefit and ROI remain unmeasured.

## Hosted model

The app controls [2024 BMW G60 by SLGA](https://sketchfab.com/3d-models/2024-bmw-g60-ee328c2302494193a05cb4949b17ae55) through the [Sketchfab Viewer API](https://sketchfab.com/developers/viewer/functions), version 1.12.1. Attribution is retained. The model's public Data API reports `isDownloadable: false`; no mesh or protected viewer assets have been extracted or bundled. The user chose the hosted model. Internet access and WebGL hardware support are required. Viewer errors are visible and can be retried.

`src/lib/sketchfab-controller.ts` is the scene adapter. It reads node/material names through the supported API rather than assuming persistent numeric IDs. Observed groups include Body, Door_Panel, Glass, Interior_Body, Seats, SteeringWheel, Lights and the four wheels. The dashboard/display is part of larger assemblies; names alone are insufficient to identify its surface. Positions for screen and vent surface projections are calibrated using the API's camera and surface-picking methods. Camera-tracked SVG overlays use the API's world-to-screen projection to remain anchored while orbiting; they are explicitly labelled x-ray concept overlays and hidden from the reverse side. They do not claim mesh occlusion. Hosted decal rendering was visually unsuitable on this model, so it is not used.

Selected seats, steering and lights pulse red by modifying their verified materials. The body and glass use adjustable transparency. Screen and vent previews use projected surface overlays on this same hosted model; they do not remodel independent screen/vent meshes. The seat After preview recolors the existing assembly in teal while preserving its original position, scale and rotation. The new finish stays visible instead of being overwritten by the red selection pulse. Show new seats previews it; the existing approval flow saves it. Baseline restores the source materials and geometry. This is a restyled assembly, not a replacement CAD asset or independently articulated seats. These are deliberately amplified design illustrations, not engineering geometry. Engine/power, brakes, battery/energy, assistance, luggage and body issues use labelled approximate x-ray region markers when independent meshes are absent. An unmatched issue gets a category-based demo region; this visual fallback does not change AI results or scores. Baseline restores original transforms and removes accepted concept projections; selection highlighting remains.

The old procedural Three.js scene remains in source for reference; the current workspace and review drawer use the hosted model throughout.

## Identification and approval

The separate `/api/v1/vehicle-target` classifier receives the problem title, description, feature/category and up to three supporting excerpts. Live AI is enabled with the user's prior authorization and has a visible off switch. Constrained component IDs and evidence validation prevent arbitrary geometry or code execution. Failure returns a clearly labelled local match and provider notice. The current API credential previously returned an authentication error; the app must not describe a local fallback as a successful live AI result.

Part identification is independent of the ten source categories. Preview selection is read-only. The existing approval dialog explicitly saves a supported `design_concept` with the decision, cohort, revision and evidence snapshot. Accepted designs are restored in the model view after refresh; rejecting/postponing/editing invalidates them while impact-band review retains them. Multiple approved presets combine. No database migration is required.

## RAG handoff

The supplied RAG engine is integrated under Document intelligence. Problems can open a document search using the selected feature and model. Retrieved answers and mapping reviews remain separate from the part classifier and approved design presets. See [RAG_INTEGRATION.md](RAG_INTEGRATION.md) for the connections and data boundaries.

## Validation

`node tests/vehicle-demo.mjs` exercises separate/merged navigation, filters, source links, selection continuity, SDK command integration, baseline/after, transparency, mobile layout and approval persistence against a disposable database and a deterministic SDK double. Backend tests validate citation provenance, constrained target identification and cohort-scoped approvals. The real model is additionally checked in a headed, GPU-enabled browser; a software-only headless browser may be rejected by Sketchfab even when local Three.js rendering works.

The earlier seat translation demo was removed after visual feedback: After and Baseline now both preserve the original seat transform. Real hosted-model screenshots were checked for screen/vent overlays, red seat materials, translucency and merged layout. `node tests/sketchfab-controller.mjs` additionally verifies projection proportions, material restoration, dynamic node discovery, unsupported-part reporting, API-error recovery and rapid selection changes.
